# 卡顿、崩溃和模型诊断

设置页的“自动保存小型转储”默认开启。转储只保存在本机，可能包含线程栈、进程中的临时文本和其他敏感内存；可以在设置页关闭。应用不会上传诊断文件。

Windows 启动时会先建立独立监控进程，再创建窗口和读取配置。监控进程每秒检查窗口的 `WM_NULL` 响应、界面心跳、运行时心跳、线程数、句柄数和内存。连续三次窗口无响应并持续五秒，或应用心跳停止十秒，才记录一次卡死；休眠恢复、最小化、没有新画面不会单独被判为卡死。恢复后重新进入冷却期，五分钟内最多保存一份转储。

卡死或未处理崩溃发生时，监控进程请求 Windows PSS 进程快照，再生成最多 50 MiB 的 `MiniDumpNormal | MiniDumpWithThreadInfo` 文件。单次取证最多运行 15 秒，失败会记录事件并释放临时文件；监控本身继续工作。转储旁边有 JSON 说明文件，包含进程身份、异常码、线程号和是否可能包含敏感栈内存。普通 panic、未处理异常和强制结束会分别记录，强制结束不保证有转储。

普通日志分为两类：事件 JSONL 和 v2 状态快照。事件队列每个进程最多 4096 条，单条最多 2 KiB；写入失败或队列满时只增加丢弃计数，不递归记录错误。快照在启动时、卡死事件发生时和每 60 秒写入。日志字段包含会话、进程、线程、构建标识、单调时钟、操作关联编号、阶段、数量和耗时；不会保存 API 密钥、凭据、配对码、对话正文、截图、音频、完整 URL 或未经处理的子进程错误文本。

普通诊断文件最多占 256 MiB，转储最多五份、总计 250 MiB，保留七天。只有本功能登记的文件会被清理；同目录中的其他文件保留。桌面目录不可写时，自动改用用户本地数据目录下的 `ale-my-eyes/Ale-My-Eyes-Logs`，设置页显示实际位置。

模型调度器使用独立持续读帧任务和顺序写入队列。单帧上限 32 MiB，最多 32 个模型任务，总在途数据 128 MiB，写入期限 3 秒。健康检查只读缓存；GPU 探测每个工具最多 2 秒、整轮最多 5 秒，并在后台刷新。模型进程连续三次无响应后按 1、2、4 秒退避重启，连续失败三次停止自动重试；旧任务得到明确失败结果，不会重放已经确认的桌面操作。

下载器分阶段报告连接、传输、解压、校验、提交和取消，使用 20 秒连接期限、60 秒无数据期限；大文件分块处理并检查取消。已有目标不会覆盖，取消会等待实际工作者退出后清理暂存目录。下载完成只表示文件已安装；运行时缺失或 GNU Windows 构建不支持本地 SenseVoice 时会单独显示。

反馈问题时，请保留发生时间、应用版本、`ale-events-*.jsonl`、`ale-diagnostic-*.json` 和同一时间的 `.dmp/.json` 文件。转储和日志都只需留在本机；不要把含有敏感内容的文件上传到公开位置。
